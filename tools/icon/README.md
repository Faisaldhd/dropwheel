# DropWheel icon pipeline

The brand mark is a **six-slice wheel** with one highlighted slice on the right and a
light hub. The badge colour is `#8224D4`, the highlighted slice `#B48AE0`, the hub
`#F5F1FB`. The mark is drawn flat: no gradients, no glow, no baked background tile.
That tile (a dark rounded square in the old `DropWheel-1024.png`) was what produced the
dark halo and the mush at 16-32 px.

## Files

| Path | Purpose |
| --- | --- |
| `branding/dropwheel-icon.svg` | hand-authored vector master (6 paths + hub circle) |
| `tools/icon/generate.py` | deterministic rasteriser / ICO writer / verifier |
| `branding/DropWheel.ico`, `src/FileAction.App/Assets/DropWheel.ico` | app icon, identical bytes |
| `branding/DropWheel-tray-{dark,light}.ico` + Assets copies | tray icons |
| `branding/DropWheel-1024.png`, `-256.png`, `Assets/DropWheel.png` | flat rasters from the same source |
| `docs/site/assets/icon/` | website set (16/32/48/128/180/256, WebP, `favicon.ico`) |
| `docs/screenshots/icon/icon-quality-sheet.png` | before/after QA sheet, generated by the script |
| `docs/screenshots/icon/before/` | frozen old frames used only by the QA sheet |

## Regenerate

```sh
python tools/icon/generate.py            # rewrites every asset + the sheet
python tools/icon/generate.py --verify   # byte-compares committed files, checks the ICO contract
python tools/icon/generate.py --sheet    # rewrites only docs/screenshots/icon/
python tools/icon/generate.py --dump     # directory dump + per-frame alpha-fringe numbers
```

The generator needs only Pillow (the repo's bundled Python already has it). No network,
no fonts, no external rasterisers. `--verify` exits non-zero on any drift, so CI can
gate the PR.

## Size contract

| Asset | Sizes | Frame storage |
| --- | --- | --- |
| `DropWheel.ico` | 16, 20, 24, 32, 40, 48, 64, 96, 128, 256 | 256 and 128 PNG; 16-96 32-bit BGRA BMP with 1-bpp AND mask |
| tray ICOs | 16, 20, 24, 32, 40, 48 | 32-bit BGRA BMP |
| `favicon.ico` | 16, 32, 48 | 32-bit BGRA BMP |
| website PNG | 16, 32, 48, 128, 180, 256 | straight-alpha PNG |

The app ICO is **98,830 bytes**, under the 120 KB budget. The budget cannot be met with
32-bit BGRA BMP for every frame below 256: 16-128 alone are 143,424 bytes of raw XOR
pixels before any header, mask or the 256 frame (`sum(size^2)*4`). To keep the committed
file under 120 KB while preserving the 256-PNG requirement, the **128 px frame is
PNG-compressed** (Vista+ supports PNG at any size); 16-96 remain 32-bit BGRA BMP. The
directory dump in `--dump` shows this explicitly.

## Alpha rules

* Every raster frame has a transparent background (`0,0,0,0`); no matte colour is baked in.
* Anti-aliasing is computed at 8x and box-filtered in **premultiplied** alpha
  (`RGBa`), then unpremultiplied. Resizing straight alpha would drag the black of
  transparent pixels into the rim - that is the old halo.
* Edge pixels keep the wedge/hub hue; a translucent pixel is never near-black.
  `--verify` fails if any frame has a pixel with `8 < alpha < 250` and luma `< 64`.
  Measured on the committed app ICO: **0 dark edge pixels out of 5,196 translucent
  edge pixels** across all ten frames. The old ICO was 100% dark fringe at 16/24/32/48/256
  (mean edge RGB `24,17,31`).
* Small sizes are hand-tuned, not downscales: each size has its own rim margin, hub
  radius, radial gap (16 px: 2 px gap and 1.4 px hub radius; 256 px: 9 px gap) and an
  alpha-contrast curve for 16-32 px.

## Geometry (measured from the old 1024 raster, then regularised)

* 6 equal slices, 60 deg each.
* Gap centres at 30/90/150/210/270/330 deg - 12, 2, 4, 6, 8 and 10 o'clock.
* Highlighted slice: the right-hand slice, 60 deg, centred on 3 o'clock.
* Hub radius 22.2% of the wheel radius (111 / 500 in the SVG viewBox).
* Radial gap 24 px at the rim in the 1024 master (2.4% of the wheel diameter); each
  smaller raster uses a gap that stays >= 2 px at 16-24 px.
* Outer radius 500/512 in the SVG; rasters use a 1.2-3.1% margin so the wheel optically
  fills the tile without touching the edge.

**Same mark, drawn clean:** this is not a new logo. The slice count, slice angles, gap
positions, hub proportion and highlighted slice were measured from the committed 1024
PNG and tray frames. What changed is the construction: a flat vector master instead of a
raster with a baked dark tile, glow and a decorative arrow. The arrow was removed because
below 48 px it aliased into a smudge and is not part of the wheel; the wheel is the mark.

## Tray variants (mapping unchanged)

* `DropWheel-tray-dark.ico` = **light glyph** (`#C8A6F0` body, `#A24CFF` highlight,
  white hub) for a **dark** taskbar.
* `DropWheel-tray-light.ico` = **dark glyph** (`#5A3C86` body, `#8224D4` highlight,
  white hub) for a **light** taskbar.

The file names, paths and the `SetupIconFile` / `ApplicationIcon` wiring are unchanged.

## CI

`.github/workflows/icon-ci.yml` runs on `pull_request` and `workflow_dispatch` on
ubuntu-latest with Python 3.12, installs the pinned Pillow wheel, runs `--verify`
(reproduction check + directory/dimension/format/alpha-fringe assertions), dumps the
ICO directory, regenerates the sheet and uploads it as an artifact. It never builds or
runs DropWheel.exe.
