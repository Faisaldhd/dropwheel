# Tool windows

DropWheel 2.4.0 has **26 floating tool windows**. A tool is not a background job: choosing it on the
Tools wheel opens a card over the file, nothing is written until you press its primary button, and the
source file is only ever read (Lock is the one exception — it transforms the item in place, see
[Lock](#25-lock--toolslock)).

Every id, title and label below is the real value from `src/FileAction.Core/Strings/en.json` and
`ar.json` (1,094 keys per table, key sets and placeholders kept identical by the localization tests in
CI). Where the two languages differ, both are shown: English first, Arabic second.

The list is derived from `src/FileAction.App/UI/Tools/ToolRegistry.cs`; each tool registers itself from
its own file, so this page is generated by hand from the registry, not from a hard-coded menu.

## What every tool shares

- **Opening it.** Drag a file (or a selection), **tap Ctrl** while dragging, and drop it on the tool's
  slice on the Tools wheel. Without a mouse: select the files (or copy an image), press
  **Ctrl + Alt + Space**, pick the slice with the arrow keys and press **Enter**.
- **The card.** One borderless, rounded window, centred on the monitor under the cursor and shown
  above other windows. Drag the title bar to move it; the round **X** or **Esc** closes it.
- **The bar.** **Reset** restores the tool's documented defaults and the primary button runs the tool
  with its own verb ("Create Collage", "Merge PDFs", "Save Edited Copy"…). **Enter** runs the primary
  button too, except in Lock, which waits until its password pair matches.
- **Where the result goes.** The folder the drop resolved (the folder under the cursor when the wheel
  opened, or a folder the drag crossed, under the 2.2.3 rules); otherwise next to the source file.
  An existing file is never overwritten — the second result becomes `<name> (2).<ext>`.
- **Afterwards.** A notification says **Saved** — "<file> saved." and the window closes; failures stay
  in the window with the app's error text, and nothing partial is left behind.
- **Size and motion.** The window opens at the tool's default size, probes the media asynchronously and
  animates to the media's aspect ratio inside the tool's preview bounds (180 ms). With **Settings →
  General → Animations** off, or Windows' own animation effects off, every transition is instant.
- **Which tool opens.** Tools with the same input (Crop, Annotate, Edit Photos…) are looked up by tool
  id, so the slice you chose is the window you get, not the first one that happens to accept the file.

## Images

Six tools work on images (Collage needs two or more). A single-image tool accepts JPG/JPEG, PNG, WebP,
AVIF, TIFF, BMP, ICO and GIF; **Edit Photos** deliberately narrows that to JPG, PNG, WebP, HEIC, TIFF,
AVIF and BMP so animations and icon frames are never flattened.

### 1. Crop Image — `tools.crop`

| | |
|---|---|
| **Title** | Crop Image · قصّ الصورة |

| **Produces** | `<name> Cropped.<ext>` — same format, EXIF orientation applied first. |

## Video

Seven tools work on video (Join needs two or more). All of them need **FFmpeg**: without it the
slices stay on the wheel dimmed with "get FFmpeg", and the window says so instead of failing silently.
Legacy containers (AVI, WMV, FLV, MPG/MPEG, 3GP, TS/MTS) are written as MP4; MP4, MOV, MKV and WebM
keep their container.

## Not shipped in 2.4.0

Every gap below names who owns it, so nobody reads a limit as "forgotten".

- **Redact image: face detection.** Manual areas and OCR text detection ship; a face detector needs
  either the Windows SDK projection this build does not carry or a new third-party package.
  **Owner: none assigned** (recorded in `RedactTool`'s own remarks and in `docs/BACKLOG.md`).
- **QR: code creation.** The tool only reads codes. **Owner: none**, not planned for 2.4.x — the
  append-only `tool.qr.copyClose` key (copy-then-close label) is an additive string for the reader, not a
  generator.
- **Lock is Beta.** The container format, the Rescuer envelope and crash recovery are covered by tests,
  but the owner has not signed the feature off. **Owner: owner sign-off, tracked as a release gate.**
- **Per-window bilingual rendering gate** (every window in English and Arabic at 100/150/200 % DPI):
  **`audit/selftest`, PR #37, in flight.** Until it is green the provable claim is the one used in this
  document: 1,094 keys per table, with key-set and placeholder parity enforced by `LocalizationTests` in
  CI. No document claims per-window Arabic rendering before that gate exists.
- **Light-mode contrast and the video timer:** **`audit/amotion` / `audit/adesign`, in flight** — they do
  not change how a tool is opened or what it writes.
- **Title Case of five existing tool labels** (`Redact image`, `Redact video`, `Save frames`,
  `Password protection`, `Remove password`) **and the `Annotate` / `Bleep Audio` primaries** that still
  say "Apply": **deferred to `docs/BACKLOG.md`** (the string tables are append-only this close to the
  tag and the pass needs an Arabic review).
