### Icons

`dropwheel-32.png` and `dropwheel-256.png` are already at the fixed point of Pillow's lossless PNG
encoder: re-saving at `optimize=True, compress_level=9` returns byte-identical files, so there is no
lossless win available with the bundled toolchain. Do not quantise them — that would change the icon.
The 256 px PNG is 52,660 B but **is not fetched by a normal page load** (apple-touch-icon / OG only).

## 3. Width variants — and why there is no 480/960 set

The real captures are **442×442** (wheel) and **420–480 px wide** (tools). A `-960.webp` would be a
2.0–2.3× *upscale* of pixels that were never rendered: softer than the native file while costing more
bytes, and it would misrepresent the capture. This lane does not upscale, so the honest srcset is
native width + a phone-width 1x variant:

| usage | CSS display width (current CSS) | candidates | note |
| --- | --- | --- | --- |
| hero wheel (`wheel-still`, `.hero-motion`) | `min(100%, 470px)`; ~354 px on a 390 px phone | `360w`, native `442w` | 442 is the max real capture; at 470 CSS the browser already upscales 1.06× (pre-existing). |
| tool cards (`.tool-shot` inside a 4:3 `.tool-media`, `inset:14px`, `object-fit:contain`) | layout box ≈ 248 px desktop / ≈ 326 px at 390 px; rendered content ≈ 117–326 px | `320w`, native `420–480w` | native is the 2x candidate on desktop; on a DPR-2 phone it is still < 2× of 326 px because the capture is not that large. |

Names follow the real width: `wheel-dark-poster-360.webp`, `crop-dark-320.webp`. The original paths
(`wheel-dark-poster.webp`, `crop-dark.webp`, …) are unchanged and remain the no-srcset fallback, so
the page cannot break by adopting only the recompressed originals.

### 4c. Required `app.js` patch (lead-owned file)

`paintThemeImages()` currently sets only `img.src`; per the HTML spec `srcset` wins over `src`, so
pasting srcset without this patch would freeze the dark/light swap. `paintMotionPicture()` also
recreates `<source>` without `sizes`. Patch the four functions as follows (behaviour is unchanged
when the new `data-*-srcset` attributes are absent):

```js
  function addSource(picture, media, source, srcset) {
    var element = document.createElement('source');
    var image = picture.querySelector('img');
    element.setAttribute('type', 'image/webp');
    if (media) {
      element.setAttribute('media', media);
    }
    element.setAttribute('srcset', srcset || source);
    if (srcset) {
      element.setAttribute('sizes', image.getAttribute('sizes') || '100vw');
    }
    picture.insertBefore(element, image);
  }

  function paintMotionPicture(picture) {
    var image = picture.querySelector('img');
    if (!image) {
      return;
    }
    var dark = currentTheme() === 'dark';
    var poster = picture.getAttribute(dark ? 'data-poster-dark' : 'data-poster-light');
    var posterSet = picture.getAttribute(dark ? 'data-poster-dark-srcset' : 'data-poster-light-srcset');
    var clip = picture.getAttribute(dark ? 'data-clip-dark' : 'data-clip-light');
    var clipSet = picture.getAttribute(dark ? 'data-clip-dark-srcset' : 'data-clip-light-srcset');

    var old = picture.querySelectorAll('source');
    for (var i = 0; i < old.length; i += 1) {
      old[i].parentNode.removeChild(old[i]);
    }

    image.removeAttribute('srcset');

    if (isReduced() || !clip) {
      addSource(picture, null, poster, posterSet);
      image.setAttribute('src', poster);
      return;
    }

    addSource(picture, '(prefers-reduced-motion: reduce)', poster, posterSet);
    addSource(picture, null, clip, clipSet);
    image.setAttribute('src', poster);
  }
```

Replace `paintThemeImages()` with:

```js
  function paintThemeImages() {
    var dark = currentTheme() === 'dark';

    var images = document.querySelectorAll('img[data-dark][data-light]');
    for (var i = 0; i < images.length; i += 1) {
      var image = images[i];
      var source = dark ? image.getAttribute('data-dark') : image.getAttribute('data-light');
      var srcset = dark ? image.getAttribute('data-dark-srcset') : image.getAttribute('data-light-srcset');
      var media = image.closest ? image.closest('.tool-media') : null;
      if (media) {
        var play = media.querySelector('.tool-play');
        if (play && play.getAttribute('aria-pressed') === 'true') {
          var clip = dark ? play.getAttribute('data-clip-dark') : play.getAttribute('data-clip-light');
          if (clip) {
            source = clip;
            srcset = null;
          }
        }
      }
      if (srcset) {
        image.setAttribute('srcset', srcset);
      } else {
        image.removeAttribute('srcset');
      }
      if (source && image.getAttribute('src') !== source) {
        image.setAttribute('src', source);
      }
    }

    var pictures = document.querySelectorAll('picture[data-motion]');
    for (var j = 0; j < pictures.length; j += 1) {
      paintMotionPicture(pictures[j]);
    }
  }
```

Replace `setPlayState()` with:

```js
  function setPlayState(button, pressed) {
    var media = button.closest ? button.closest('.tool-media') : null;

        image.setAttribute('srcset', srcset);
      } else {
        image.removeAttribute('srcset');
      }
      if (source) {
        image.setAttribute('src', source);

    }
    paintPlayButton(button);

```

## 5. First-load accounting

The page lazy-loads tool media and the lock badges (`loading="lazy"` below the fold). Normal first
load of the dark theme, motion allowed:

| request | bytes |

- `icon/dropwheel-256.png` (52,660 B) is not fetched by page load; it is only for apple-touch-icon
  and social crawlers.
- Lock badges (10,256 B total) and all tool posters/clips are lazy; they do not count toward first

- Current text assets in this worktree are `index.html` 106,383 B + `styles.css` 45,394 B +
  `app.js` 15,156 B + `boot.js` 1,244 B = 168,177 B uncompressed (lead's lane), so an uncompressed
  first load is ≈ 228 KB; GitHub Pages gzip makes the text part smaller. No webfont is referenced.
- Hero-critical set: 11,870 + 53,978 + 3,644 + (2,236 + 2,438 + 2,756 + 2,826) = **79,748 B**.

## 6. Reproduce and verify

Use the bundled interpreter (Pillow 12.3.0, Python 3.12.14); do **not** `pip install` into system
Python. The script only needs Pillow.

```bat
<bundled-python>\python.exe scripts\site\optimize_media.py            :: write + byte table
<bundled-python>\python.exe scripts\site\optimize_media.py --check    :: verify committed bytes
<bundled-python>\python.exe scripts\site\optimize_media.py --markdown :: machine-readable table
```

- Every output is decoded from the committed source on every run: the script is idempotent and the
  output is byte-identical across runs (verified twice, and from a pristine `git archive 7009be9`
  checkout).
- Quality ladders and frame timings are fixed in the script; animated WebP keeps the source frame
  count, per-frame durations and `loop=0` (checked frame-by-frame).
- Exit code is non-zero if any per-file target, the 110,000 B hero-critical budget, or the 4,000,000 B
  asset total is exceeded, if any original file would grow, or if `--check` finds stale output.
- `.gitignore` contains a bare `tools/` rule. New files under `docs/site/assets/tools/` are therefore
  ignored by `git add` and must be staged with `git add -f`. The ten `*-320.webp` variants are already
  tracked; this only matters when new files are generated there.

## 7. What not to ship

- `docs/screenshots/en/*.png` — stale orange 2.3.x screenshots (598,270 B across 5 files). Not
  referenced by `docs/site/index.html`; keep them out of the site and out of any preload.
- The poster **PNG** sources in `docs/screenshots/motion/` (23–74 KB each) — capture sources only.
- `icon/dropwheel-256.png` in the page body or a `<link rel="preload">` — 52,660 B for a
  crawler/install-only asset.
- The 12 new width variants **unless** the 4c patch lands. Without it they are dead repo bytes (still
  never downloaded). If the lead prefers no JS change, dropping them keeps the site at 656,245 B with
  zero behavioural risk.
- Keep the native 442/480 poster files even after adopting srcset: they are the only high-density
  real captures and the no-srcset fallback.

## 8. Could not verify / limits

- No browser, no Lighthouse, no local page open (hard rule) — the budget is byte arithmetic on the
  committed files, not a measured waterfall. Visual proof must come from GitHub Actions.
- The app.js patch in 4c is specified but not applied (file owned by the lead) and therefore not
  runtime-tested here; variants are inert until it lands.
- The hero capture is 442 px wide while CSS can display 470 px, so desktop still upscales it 1.06×.
  Fixing that needs a re-render at ≥470 px, not re-encoding.
- Animated clips are lossy WebP at q68–82 (stills q82–90); stills measure 37–42 dB PSNR against the
  PNG source and were spot-checked for small-text legibility. Pixel-identical delivery was not a goal
  and is not possible below the byte targets.
