## Verdict

The page is ready for **content review**, but it is **not publishable to Pages yet**:

1. There is no verified 2.4.0 GitHub release, so the live CTA must keep pointing at the last
   signed release (2.3.0). The page says so explicitly.
2. Lighthouse has **not** been run: no Lighthouse/LHCI binary is installed in this
   environment. The “Lighthouse ≥ 95” requirement is therefore open and must be measured in CI
   or on the deployed URL before publication.
3. Only 5 of the 26 registered tool windows have real captures. The other 21 use a deliberate,
   clearly decorative tile (category + index), never a mock-up of the tool window. The brief said
   “all 25 tool windows”; the registry actually contains **26** (`tools.lock` was merged as the
   26th), so the missing count is 21, not 20.

Everything else in the brief is implemented and was verified locally: purple identity with a
dark/light toggle, EN/AR with RTL, wheel explainer, 26 tool windows with 7 filter chips, Protect/
Lock with the Rescuer password + recovery key and real badge captures, the format matrix, the
privacy line verbatim, the 2.4.0 changelog, SHA-256/ECDSA verification, FAQ, footer, WebP,
lazy loading, `prefers-reduced-motion`, and a first load of **222 KiB** (well under 500 KB).

## Size budget (measured locally)

Method: every file byte size from the working tree, plus a headless-Chrome (155) CDP run against
`python -m http.server 8123 --directory docs/site`, with `localStorage` set for theme/language and
`performance.getEntriesByType('resource')` read after load. The document was counted separately
because the Resource Timing API does not include the navigation document.

| Scenario | Files | Total | Budget |
|---|---:|---:|---:|
| Critical path (document, CSS, JS, hero clip, icon, favicon) | 7 | **227,748 B (222.4 KiB)** | < 500 KB |
| Critical path + wheel poster (loaded just below the fold) | 8 | 240,448 B (234.8 KiB) | < 500 KB |
| Measured network, dark, desktop 1440×1000 | — | ~238 KiB (105 KB document + 133 KB subresources) | < 500 KB |
| Measured network, light, desktop | — | ~314 KiB | < 500 KB |
| Whole site, all assets | 37 | **885,315 B (864.6 KiB)** | not budgeted |

Why light is larger: the theme swap happens after `boot.js`; the browser starts the dark variants
of the lazily loaded tool/lock images and then fetches the light ones. Still under half the
budget. If this matters later, delay the theme `src` swap until a card is near the viewport.

The full page weighs ~700 KiB of images after every lazy image is loaded; that is expected for 29
WebP assets and is not part of the first-load budget.

## Accessibility

Implemented:

- landmarks (`header`, `nav`, `main`, `footer`), one `h1`, a skip link that is off-screen until
  focused;
- visible `:focus-visible` ring on every interactive element; native `<details>` FAQ; no
  keyboard traps;
- `aria-pressed` on theme-like filter chips and language buttons; `aria-live` for the filter
  count and copy feedback; `aria-controls` from chips to the grid;
- every image has a text alternative or is explicitly decorative; tool-window alt text switches
  with the UI language;
- the language switch also updates `aria-label`s, `alt`s, `<title>`, description and Open Graph
  metadata;
- Arabic uses Western digits, `bdi` isolation for versions/hashes/paths, and zero letter-spacing
  (letter-spacing breaks Arabic joins);
- `prefers-reduced-motion` removes the animated sources, serves posters and hides the motion
  buttons; `prefers-contrast: more` strengthens borders;
- no colour-only state: active chips are filled **and** `aria-pressed`; links are underlined on
  hover/focus.

## Lighthouse

Not measured locally: there is no Lighthouse or Lighthouse-CI installation, and installing one
would require network/package changes outside this task. The page is built to score well
(no frameworks, system fonts, one small CSS file, 16 KB JS, explicit dimensions, lazy images,
same-origin assets, no third-party tags), but “expected” is not “measured”.

Required before publishing (desktop and mobile):

```powershell
npx lighthouse https://faisaldhd.github.io/dropwheel/ --preset=desktop --quiet `
  --chrome-flags="--headless" --output=json --output-path=./lighthouse-desktop.json
npx lighthouse https://faisaldhd.github.io/dropwheel/ --quiet `
  --chrome-flags="--headless" --output=json --output-path=./lighthouse-mobile.json
```

or add `treosh/lighthouse-ci-action` to a CI workflow with `urls: https://faisaldhd.github.io/dropwheel/`
and `assert.assertions: { categories:performance: ["error", {minScore: 0.95}], categories:accessibility:
["error", {minScore: 0.95}], categories:best-practices: ["error", {minScore: 0.95}], categories:seo:
["error", {minScore: 0.95}] }`. The existing `pages.yml` only uploads/deploys; it has no audit step.

- **2.4.0 release missing** — the page is intentionally a staged 2.3.0-download page with a 2.4.0
  changelog. Do not publish before the release.
- **Lighthouse not measured** — blocking for the “≥ 95” requirement.
- **21 missing tool captures + Arabic captures + Tools/Actions wheel** — visible gap; the
  decorative tiles are honest, but the brief’s “all windows with real screenshots” is not met.

- **Long mobile page** — 26 single-column cards plus sections; filters are the mitigation. Consider
  a compact list or 2-column layout on phones in a later pass.
