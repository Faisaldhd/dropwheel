# WCAG 2.2 AA audit — `docs/site` (finding list)

Lane: **site** · Owner: **site-seo** · Branch: `site/seo`.
Audited: `docs/site/index.html` (1,076 lines), `docs/site/assets/styles.css`
(1,611 lines), `docs/site/assets/app.js` (441 lines), 2026-10-20.

Method and limits: static source review only — no browser, no local server, no
automated axe run (the lane rules forbid opening the page locally). Contrast is
computed from the literal token values in `styles.css` using the WCAG relative
luminance formula, with alpha composited onto the actual background behind each
token. Numbers below are reproducible from the pairs listed. Anything that can
only be judged in a render is marked **[render check]** and is not counted as a
finding.

Five must-fix items, then nice-to-have, then the full contrast table and the
list of things that were checked and are clean.

## Must fix

### M1 — Gradient headings disappear in Windows High Contrast / forced colours

**Files:** `styles.css:142-151` (`h1`), `styles.css:1128-1136` (`.privacy-panel h2`).
**SC:** 1.4.1 Use of Color, 1.4.3 Contrast (Minimum) — the text becomes invisible, not just low contrast.

Both headings set `background: linear-gradient(...)`, `background-clip: text`,
`color: transparent` and rely on the gradient painting the glyphs. In
`forced-colors: active` (Windows Contrast Themes) the UA drops author backgrounds,
so the fill disappears and the text renders as transparent-on-canvas. The page
already ships a `prefers-contrast: more` block (`styles.css:1601-1604`) but no
forced-colors fallback.

**Fix** — add after `styles.css:1604`:

```css
@media (forced-colors: active) {
  h1,
  .privacy-panel h2 {
    background: none;
    color: CanvasText;
    -webkit-text-fill-color: CanvasText;
  }
}
```

### M2 — Interactive controls have no 3:1 boundary (Non-text Contrast)

**Files:** `styles.css:15` (`--line-strong: rgba(198,160,240,0.34)`),
`:47` (light `rgba(60,40,100,0.28)`), and the controls that use it:
`.icon-button` `:335-348`, `.lang-switch` `:355-361`, `.chip` `:731-751`,
`.btn--ghost` `:414-419`, `.copy-button` `:1352-1365`, `.tool-play` `:822-844`,
`.for-it` `:1299-1305`.
**SC:** 1.4.11 Non-text Contrast.

Measured (composited over the real background, not the token alpha):

| Boundary | Colours | Ratio | Needed |
| --- | --- | --- | --- |
| dark control border over its own fill | `#56446c` on `#100b18` | **2.25:1** | 3:1 |
| dark control border over page bg | `#4e3e61` on `#100b18` | **2.02:1** | 3:1 |
| dark control fill vs page bg | `#1c1428` on `#100b18` | **1.09:1** | 3:1 |
| dark `.tool-play` border over media bg | `#514065` on `#140f1e` | **2.03:1** | 3:1 |
| light control border over white | `#c8c3d4` on `#f5f1fb` | **1.54:1** | 3:1 |
| light control fill vs page bg | `#ffffff` on `#f5f1fb` | **1.11:1** | 3:1 |

A chip, icon button, ghost button and copy button are identifiable only by that
1 px boundary — the text alone does not mark them as controls.

**Fix** — add a control-only token and leave the decorative `--line-strong` alone
(so card borders and shadows do not get heavier):

```css
:root { --control-line: rgba(198, 160, 240, 0.60); }              /* 3.8:1 on --bg */
html[data-theme="light"] { --control-line: rgba(60, 40, 100, 0.65); } /* 3.90:1 on --bg */
```

Then set `border-color: var(--control-line)` on `.icon-button` (`:342`),
`.lang-switch` (`:359`), `.chip` (`:737`), `.btn--ghost` (`:416`),
`.copy-button` (`:1358`), `.tool-play` (`:834`) and `.for-it` (`:1301`).
Solid alternatives that also pass: `#7a5fa0` dark (3.67:1), `#80739a` light
(3.90:1).

### M3 — Focus ring is clipped on the "For IT" disclosure

**Files:** `styles.css:1304` (`.for-it { overflow: hidden }`),
`styles.css:123-127` (global ring: 2 px `--accent-2`, `outline-offset: 3px`),
`index.html:954-957` (`.for-it__summary`).
**SC:** 2.4.7 Focus Visible, 2.4.11 Focus Not Obscured (Minimum).

The summary spans the full width of `.for-it`, whose `overflow: hidden` is there
to clip the rounded corners. The focus ring is drawn 3 px *outside* the summary,
so it is clipped on the top, start and end edges — the keyboard user sees a
partial or no indicator on the only focusable element of that block. The same
pattern was checked on `.tool-card` (`:788`) / `.tool-media` (`:810`): there the
`30×30` play button sits 9 px inside the media box, so its 5 px of ring is not
clipped.

**Fix** — draw that one ring inside the padding box:

```css
.for-it__summary:focus-visible { outline-offset: -5px; }
```

### M4 — Switching language announces nothing

**Files:** `app.js:199-210` (`setLanguage`), `app.js:148-181` (`applyLabels`),
`index.html:93-96` (the switch buttons).
**SC:** 4.1.3 Status Messages (AA); also the practical side of 3.2.2.

The switch rewrites `<html lang>`/`dir`, the title, the meta description, every
`aria-label` and every image `alt` — correctly — but focus stays on the button and
no live region is touched, so a screen-reader user gets no confirmation that the
page is now Arabic (or English). They discover it when the next element is read in
a different language.

**Fix** — add to `index.html` after the `.lang-switch` div (after line 96):

```html
<p class="visually-hidden" id="lang-status" role="status" aria-live="polite"></p>
```

and in `styles.css` (next to `.tool-play__text`, `:845-852`, which already uses
this technique):

```css
.visually-hidden {
  position: absolute;
  width: 1px;
  height: 1px;
  margin: -1px;
  padding: 0;
  overflow: hidden;
  clip-path: inset(50%);
  white-space: nowrap;
  border: 0;
}
```

then in `setLanguage()` (`app.js:210`, after `applyLabels()`):

```js
var status = document.getElementById('lang-status');
if (persist && status) {
  status.textContent = next === 'ar' ? 'تم التبديل إلى العربية.' : 'Switched to English.';
}
```

`persist` is already `false` on the init call (`app.js:436`), so nothing is
announced on page load.

### M5 — `overflow-x: hidden` on `body` hides reflow instead of preventing it

**File:** `styles.css:88`.
**SC:** 1.4.10 Reflow (AA) — **[render check]** for the consequence; the rule itself is verified.

`body { overflow-x: hidden }` removes the horizontal scrollbar. If any child is
wider than the viewport at 320 CSS px / 400 % zoom, the content is clipped and
unreachable instead of scrollable — the classic Reflow failure mode. The responsive
blocks (`:1504-1585`) and `pre { overflow-x: auto }` (`:1244`) suggest most content
does reflow, but this rule would mask any remaining overflow.

**Fix** — delete line 88 and let the decorative layers be clipped where they are
created (`.hero` already has `overflow: clip` at `:495`, `.privacy-panel` has
`overflow: hidden` at `:1114`, `body::before/::after` are `position: fixed`). Then
confirm at 320 px that no horizontal scroll appears.

## Checked and clean (so you do not re-audit them)

* **Skip link** — `index.html:33`, `styles.css:208-220`; fixed, moves into view on
  `:focus-visible`, target `<main id="main" tabindex="-1">` (`index.html:105`). The
  anchor also gets `scroll-margin-top: 92px` via `.section` (`:435`).
* **Landmarks** — one `<header>` banner (`:71`), one `<main>` (`:105`), one
  `<footer>` contentinfo (`:1029`); section `<header>` elements are not landmarks;
  navs are labelled (`:78`, `:1040`, `:1050`, `:1059`).
* **Heading order** — exactly one `h1` (`:114`), every section `h2` matches its
  `aria-labelledby`, cards use `h3`, no skipped level; footer `h2` (`:1041`,
  `:1051`, `:1061`) follows the last section `h2`.
* **Reduced motion** — CSS `styles.css:1589-1599` (kills animations/transitions,
  sets `scroll-behavior: auto`, hides `.tool-play`), JS
  `app.js:27`, `:305-314`, `:412-418` also hides the buttons and resets a playing
  clip; the hero `<picture>` has `prefers-reduced-motion` sources
  (`index.html:170-173`). No autoplaying media, no timers other than the 2.2 s copy
  status reset.
* **Focus visibility** — one global `:focus-visible` rule
  (`styles.css:123-127`): 2 px `--accent-2`, `outline-offset: 3px`, **7.07:1** on
  `--bg` and **6.48:1** on `--surface` dark, **8.72:1** on white (the 3:1
  non-text minimum is met with margin). Every interactive element is a native
  `button`, `a` or `summary`, so focus order follows the DOM, there are no focus
  traps, and the only `tabindex` values are `-1` on `<main>` (`index.html:105`)
  and `0` on the two scrollable `pre` blocks (`index.html:917`, `:922`) — both
  correct. The single clipping defect is M3.
* **RTL logical properties** — the layout is written in logical properties
  throughout: `inset-inline-start/end` (`styles.css:211`, `826`, `874-892`, `984`,
  `1120`), `margin-inline*` (`171`, `309`, `1296-1297`, `1320`, `1514`, `1520`,
  `1533`), `padding-inline*` (`471`, `758`, `977`), `border-inline-start` (`472`),
  plus `margin-block`/`padding-block` (throughout), `dir`-aware icon mirroring
  (`264-265`, `425-426`, `1492`) and forced-LTR code blocks (`1485-1487`).
  Three physical values remain, all cosmetic and listed as N3/N4; the decorative
  spotlights at `12% -4%` and `104% 4%` (`96-100`) are also physical and do not
  mirror — intentional, no fix needed.
* **Language of parts** — every Arabic string carries `lang="ar"` (e.g.
  `index.html:62`, `:117`, `:722`) and Latin technical values are isolated with
  `dir="ltr"` / `<bdi>` (`:59`, `:151`, `:966`). `app.js:164-170` swaps `alt` text
  per language and `:152-162` swaps `aria-label`s.
* **Keyboard access to the tool filters** — real `<button>`s with `aria-pressed`
  and `aria-controls` (`index.html:263-271`), filtering uses the `hidden`
  attribute (`app.js:219`, honoured by `[hidden]` at `styles.css:119`), and the
  result count goes to a polite live region (`index.html:272`,
  `app.js:238-253`). Focus never lands in a hidden card.
* **`details`/`summary` IT block** — native disclosure (`index.html:953-969`), so
  Enter/Space and expanded state come from the platform; the visible `+`/`−` is
  `::after` (`styles.css:1318-1326`) and the default marker is only hidden, not
  replaced by a fake control. Only the ring clipping is a finding (M3).
* **Images** — decorative SVGs are `aria-hidden` (`index.html:35`, all `<use>`
  icons); the brand mark is `alt=""` inside a labelled link (`:74`, `:1034`);
  content images have descriptive `alt` that is translated (`:175-177`, `:279-280`,
  `:718-721`).
* **Zoom / scaling** — no `maximum-scale` or `user-scalable=no` in the viewport tag
  (`index.html:5`); `text-size-adjust: 100%` (`styles.css:74-75`).
* **No forms, no autoplay, no flashing content, no CAPTCHA, no timed content.**
